# 音视频会话服务（多人版）

这是一个不依赖 WebRTC、WebSocket 或外部通信平台的 Go 原型。参与者通过进程内本地信箱交换提案，媒体数据由本地模拟源生成。

## 已实现

- 多人会话：成员可加入、离开；离开时其发布的轨道被释放，并从其他轨道的订阅列表中移除。
- 能力协商：轨道方向、编码、码率、采样率、声道数、分辨率必须落在共同范围内。
- 部分生效：一次变更可能只被部分参与者确认。版本状态为 \`partial\`，\`Session.Scope\` 明确列出已确认成员，未确认或被拒绝的成员（\`Declined\`）不会显示成全体一致。
- 轨道订阅调整：成员可单方面订阅/退订活动轨道，变更作为独立版本写入协商历史。
- 轨道归属：每条活动轨道记录 \`Publisher\` 与 \`Subscribers\`，每端只能看到（并产出）自己发布或订阅的轨道。
- 交叉提案：双方都未获答复的并发提案按发起方 ID 字典序固定规则裁决；已有部分确认的版本会被更新的提案取代，旧版本记录为 \`superseded\`。
- 版本保护：迟到或重复答复绑定原版本号，非 \`proposing\`/\`partial\` 状态返回 \`stale\`，不能覆盖新决定。
- 断开与恢复：离线成员的消息在本地信箱排队，重连后按顺序投递；\`SyncView\` 让该成员追平到当前可参与状态，而不是发起新提案覆盖他人决定。
- 失败回滚：参数无共同范围时该答复者记入 \`Declined\`，其余已确认范围不受影响；两端会话中无人接受则整体 \`rejected\`，旧会话保留。
- 独立持久化：会话、轨道、协商版本分别写入 \`sessions.json\`、\`tracks.json\`、\`versions.json\`，重启后逐端核对轨道归属与完整协商历史。
- 模拟媒体：\`LocalMediaSource\` 按端过滤可见轨道生成帧，后续可替换成真实 RTP/SRTP 或其他传输层。

## 运行

\`\`\`bash
go test ./...
go run . -data /tmp/avsession-demo
\`\`\`

演示会依次展示：

1. 两端初始协商。
2. Carol 与 Dave 同时加入会话。
3. 全员提案中 Carol 视频编码冲突，只有部分人生效，生效范围明确列出。
4. Carol 单方面订阅 audio-1。
5. Dave 发布屏幕轨道 screen-1（Carol 仍未纳入）。
6. Carol 离线期间 Dave 移除 video-1，Carol 重连后追平到当前状态，迟到答复被拒绝。
7. Dave 离开，其发布的 screen-1 被释放。
8. 从磁盘重建服务，逐端核对轨道归属并打印完整协商历史。

## 代码结构

- \`model.go\`：会话、轨道、能力、提案、协商版本和消息模型。
- \`store.go\`：原子 JSON 持久化，三类数据分开保存。
- \`negotiate.go\`：共同范围求交、轨道状态生成、发布者/订阅者合并。
- \`service.go\`：多人会话版本机、成员管理、订阅调整、冲突裁决、接受/拒绝和回滚。
- \`bus.go\`：离线可恢复的进程内本地信箱。
- \`endpoint.go\`：模拟端如何发送/处理协商消息、广播提案与重连追平。
- \`media.go\`：本地模拟媒体帧，按端过滤可见轨道。
- \`main.go\`：多人端到端演示和示例能力配置。
- \`service_test.go\`：关键一致性规则测试。

## 后续接入真实传输

本版将协商状态与传输解耦。后续可以保留 \`Service\` 的版本机，把 \`Bus\` 和 \`LocalMediaSource\` 分别替换为实际信令通道与 RTP/SRTP 收发器；活动轨道以协商成功后持久化的 \`TrackState\`（含发布者与订阅者）作为传输配置来源。
