# 音视频会话服务（第一版）

这是一个不依赖 WebRTC、WebSocket 或外部通信平台的 Go 原型。两端通过进程内本地信箱交换提案，媒体数据由本地模拟源生成。

## 已实现

- 双方能力协商：轨道方向、编码、码率、采样率、声道数、分辨率必须落在双方共同范围内。
- 会话变更：新版本接受后整体替换活动轨道；停用或无交集的轨道不进入会话状态，相当于释放对应状态。
- 独立持久化：会话、轨道、协商版本分别写入 `sessions.json`、`tracks.json`、`versions.json`。
- 固定冲突规则：双方同时发起变更且已有待决版本时，按双方 ID 字典序较小者获胜；失败版本记录为 `superseded`。
- 版本保护：只有当前处于 `proposing` 的版本能接受答复；迟到答复返回 `stale`，不能覆盖新版本。
- 失败回滚：参数无共同范围时版本记录为 `rejected`，会话继续保留上一版活动轨道。
- 断开与恢复：对端离线时消息进入本地信箱，重连后按顺序投递，两端追平到同一协商版本。
- 模拟媒体：`LocalMediaSource` 只为当前活动轨道生成帧，后续可替换成真实 RTP/SRTP 或其他传输层。

## 运行

```bash
go test ./...
go run . -data /tmp/avsession-demo
```

演示会依次展示：

1. 交叉提案与固定规则冲突。
2. 旧版本迟到答复不能覆盖新版本。
3. 一端离线、消息排队、重连后停用视频并释放状态。
4. 编码无共同范围导致协商失败，但旧会话保持不变。

## 多人房间（参与身份与按参与者订阅）

在不改动原两端版本机的前提下，新增了并行的多人房间子系统：

- 参与身份（generation）：同名用户每次加入得到 `name#generation` 形式的新 pid；离开后重入是两次不同参与。信箱、待决项和订阅全部按完整 pid 记录，旧连接的迟到答复、取消通知或轨道消息会被拒绝（`ErrStaleParticipant`），不能影响新连接。
- 多人发布与按参与者订阅：任何在场参与者都可发布轨道；发布立即可见，但只有目标参与者逐项接受后才产生媒体。一次调整为每个接收者生成独立条目，逐端展示 `accepted`、`pending`、`rejected`、`cancelled` 范围。
- 部分接受：一次提案可以只被部分参与者接受；生效参数按“发布能力 ∩ 接收能力 ∩ 请求 ∩ 答复”逐端求交，各端可见轨道与参数互不影响。
- 离开规则：保留离开前已经做出的决定；撤回只涉及离开者的生效订阅和待决项，发布者离开会停止其轨道来源，其他成员之间的独立协商继续。新人加入不会替缺席的同名旧身份接受旧提案。
- 交叉提案：同一轨道上的多个提案各自记录 `based_on` 状态、发起参与身份和逐项决定，不同参与身份的同意不会被拼成一次“全体接受”。
- 撤回与重入：接收者可显式退订；撤回/拒绝记录按参与身份永久保留，不会因为显示名称相同而自动恢复，重入者必须在概况中重新显式订阅。
- 轨道标识复用：轨道历史按 `(id, owner_generation)` 区分来源。同名重入者重新使用同一 ID 时，旧订阅与媒体帧不会串到新来源。
- 断线恢复：重连者通过 `Resync`/概况重新取得当前可参与轨道、在场者和协商状态；信箱按 pid 隔离，旧 pid 排队消息不会投递给新 pid。
- 持久化与幂等：房间整体写入 `room-<id>.json`；恢复进程后重放同一答复是幂等的，不会重复修改协商或生成重复订阅。
- 本地媒体：`RoomMediaSource` 只按某参与身份当前 `active` 的订阅产帧，帧带轨道 ID、来源世代、接收者和生效参数，便于逐端核对。

多人演示（不连接真实通话服务）：

```bash
go run . -room -data /tmp/avsession-room-demo
```

演练覆盖：部分接受后离开、同名重入、显式重新订阅、轨道移除与旧答复同时到达、恢复保存状态后重复答复，以及旧参与身份迟到答复被拒绝。

## 代码结构

- `model.go`：会话、轨道、能力、提案、协商版本和消息模型。
- `store.go`：原子 JSON 持久化，三类数据分开保存。
- `negotiate.go`：共同范围求交和轨道状态生成。
- `service.go`：会话版本机、冲突裁决、接受/拒绝和回滚。
- `bus.go`：离线可恢复的进程内本地信箱。
- `endpoint.go`：模拟端如何发送/处理协商消息。
- `media.go`：本地模拟媒体帧。
- `main.go`：端到端演示和示例能力配置。
- `service_test.go`：关键一致性规则测试。
- `room_model.go` / `room_service.go` / `room_helpers.go` / `room_overview.go`：多人房间模型、参与身份版本机、逐项协商、参数求交和概况。
- `room_bus.go` / `room_endpoint.go` / `room_media.go` / `room_demo.go`：按参与身份隔离的可恢复信箱、房间端点、模拟媒体源和多人演练。
- `room_test.go`：部分接受、离开、同名重入、迟到答复、交叉提案、ID 复用、幂等重放和逐端媒体核对测试。

## 后续接入真实传输

第一版将协商状态与传输解耦。后续可以保留 `Service` 的版本机，把 `Bus` 和 `LocalMediaSource` 分别替换为实际信令通道与 RTP/SRTP 收发器；活动轨道以协商成功后持久化的 `TrackState` 作为传输配置来源。
