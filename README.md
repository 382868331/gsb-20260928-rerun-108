# 音视频会话服务（第二版：多人参与世代）

不依赖 WebRTC、WebSocket 或外部通信平台的 Go 原型。成员通过进程内本地信箱交换提案，媒体数据由本地模拟源生成。

## 已实现

- 双方/多方能力协商：轨道方向、编码、码率、采样率、声道数、分辨率必须落在所有接受者的共同范围内。
- 参与身份与世代：每次加入生成独立 Participation（carol、carol#2…）；同名重入不复用旧连接身份，旧身份的消息与答复一律被拒绝或忽略。
- 按参与者的轨道来源：每条 TrackState 记录 Owner/Publisher/SourceID 与 Subscribers；SessionFor 只返回该参与者拥有或明确接受且仍有效的来源。
- 多人版本机：提案按在场目标收集答复，部分接受为 partially_accepted；只有当前世代且仍在场的目标全部接受才整体生效，绝不把不同参与世代的同意拼成全体接受。
- 成员离开：成员版本（membership）记录移除，离开者发布的轨道被撤回、从他人订阅列表剔除，其迟到同意返回 ErrParticipant，不再计入进行中的提案。
- 轨道编号复用：离开者轨道撤回后，新世代可用相同轨道 ID 重新发布，互不冲突。
- 幂等答复：同一世代对同一版本的重复答复是无副作用的空操作；版本完结后的迟到答复返回 stale。重启重载后规则不变，旧决定保留在 versions.json 可查。
- 固定冲突规则：同时发起变更时按发起者 ID 字典序较小者获胜，失败版本记录为 superseded。
- 失败回滚：参数无共同范围时版本记录为 rejected，会话保留上一版活动轨道。
- 断开与恢复：离线期间消息进入本地信箱，重连后按顺序投递；失效身份的端点会忽略发给旧参与的消息。
- 独立持久化：会话（含参与记录）、轨道、协商版本分别写入 sessions.json、tracks.json、versions.json。

## 运行

    go test ./...
    go run . -data /tmp/avsession-demo

演示依次展示：

1. 部分成员接受（Carol 离线，仅 Bob 答复，版本保持 partially_accepted）。
2. 成员离开与迟到同意同时发生：离开后提案按剩余在场目标完结，旧身份同意被拒绝。
3. 同名重入生成新参与世代 carol#2，旧身份消息不影响新身份。
4. 原轨道编号由新世代重新使用，并按参与者展示各自视角与本地媒体帧。
5. 保存重开后重复答复：已完结版本返回 stale，进行中版本幂等无重复效果。

## 代码结构

- model.go：会话、参与世代、轨道、能力、提案、协商版本和消息模型。
- store.go：原子 JSON 持久化，三类数据分开保存。
- negotiate.go：共同范围求交与单轨道状态生成。
- service.go：参与世代管理、多人版本机、冲突裁决、按参与者视图。
- bus.go：离线可恢复的进程内本地信箱。
- endpoint.go：绑定参与身份的模拟端，自动忽略旧身份消息。
- media.go：本地模拟媒体帧。
- main.go：多人端到端演示。
- service_test.go：两人一致性规则与多人世代/订阅/幂等测试。

## 后续接入真实传输

协商状态与传输解耦。后续可保留 Service 的版本机，把 Bus 和 LocalMediaSource 分别替换为实际信令通道与 RTP/SRTP 收发器；活动轨道以协商成功后持久化的 TrackState（含 Owner/SourceID/Subscribers）作为传输配置来源。
