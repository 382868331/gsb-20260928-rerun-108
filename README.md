# 音视频会话服务（第一版）

这是一个不依赖 WebRTC、WebSocket 或外部通信平台的 Go 原型。两端通过进程内本地信箱交换提案，媒体数据由本地模拟源生成。

## 已实现

- 双方能力协商：轨道方向、编码、码率、采样率、声道数、分辨率必须落在双方共同范围内。
- 会话变更：新版本接受后整体替换活动轨道；停用或无交集的轨道不进入会话状态，相当于释放对应状态。
- 独立持久化：会话、轨道、协商版本分别写入 `sessions.json`、`tracks.json`、`versions.json`。
- 固定冲突规则：双方同时发起变更且已有待决版本时，按双方 ID 字典序较小者获胜；失败版本记录为 `superseded`。
- 版本保护：只有当前处于 `proposing` 的版本能接受答复；迟到答复返回 `stale`，不能覆盖新版本。
- 失败回滚：参数无共同范围时版本记录为 `rejected`，会话继续保留上一版活动轨道。
- 断开与恢复：对端离线时消息进入本地信箱，重连后按顺序投递，两端追平到同一协商版本。
- 模拟媒体：`LocalMediaSource` 只为当前活动轨道生成帧，后续可替换成真实 RTP/SRTP 或其他传输层。

## 运行

```bash
go test ./...
go run . -data /tmp/avsession-demo
```

演示会依次展示：

1. 交叉提案与固定规则冲突。
2. 旧版本迟到答复不能覆盖新版本。
3. 一端离线、消息排队、重连后停用视频并释放状态。
4. 编码无共同范围导致协商失败，但旧会话保持不变。

## 代码结构

- `model.go`：会话、轨道、能力、提案、协商版本和消息模型。
- `store.go`：原子 JSON 持久化，三类数据分开保存。
- `negotiate.go`：共同范围求交和轨道状态生成。
- `service.go`：会话版本机、冲突裁决、接受/拒绝和回滚。
- `bus.go`：离线可恢复的进程内本地信箱。
- `endpoint.go`：模拟端如何发送/处理协商消息。
- `media.go`：本地模拟媒体帧。
- `main.go`：端到端演示和示例能力配置。
- `service_test.go`：关键一致性规则测试。

## 后续接入真实传输

第一版将协商状态与传输解耦。后续可以保留 `Service` 的版本机，把 `Bus` 和 `LocalMediaSource` 分别替换为实际信令通道与 RTP/SRTP 收发器；活动轨道以协商成功后持久化的 `TrackState` 作为传输配置来源。
